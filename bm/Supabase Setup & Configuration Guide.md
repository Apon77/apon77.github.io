# Supabase Setup & Configuration Guide — Secure Bookmark Manager

This document records the complete Supabase backend architecture, table schema, security rules, and RPC functions implemented for your static GitHub Pages bookmark manager (`apon77.github.io`).

---

## 1. Database Schema (`bookmarks` Table)
The database uses a single table named `bookmarks` designed to store links, organizational categories, tags, and separate click-tracking metrics.

Run the following SQL in your Supabase **SQL Editor** to create or update the table structure:

```sql
-- Create bookmarks table with all required fields
create table if not exists bookmarks (
  id bigint generated by default as identity primary key,
  user_id uuid references auth.users not null,
  title text not null,
  url text not null,
  folder text default 'General',
  tags text[] default '{}',
  user_click_count bigint default 0,
  public_click_count bigint default 0,
  created_at timestamp with time zone default timezone('utc'::text, now()) not null
);
```

---

## 2. Row Level Security (RLS) Model
To ensure that anyone on the public internet (`apon77.github.io`) can view your bookmarks and click counts, but **only you** can add, edit, or delete items, Row Level Security is strictly enforced.

```sql
-- Enable RLS on the table
alter table bookmarks enable row level security;

-- Policy 1: Public Read Access (Anon & Authenticated can view all rows)
create policy "Public read access"
on bookmarks
for select
to anon, authenticated
using (true);

-- Policy 2: Authenticated Insert Access (Only logged-in owner can add)
create policy "Authenticated insert access"
on bookmarks
for insert
to authenticated
with check (auth.uid() = user_id);

-- Policy 3: Authenticated Update/Delete Access (Only logged-in owner can edit/delete)
create policy "Authenticated update/delete access"
on bookmarks
for all
to authenticated
using (auth.uid() = user_id)
with check (auth.uid() = user_id);
```

## 3. Secure Click Counter RPC Function
To allow public visitors to increment hit counts without granting them permission to modify or delete bookmark data, a secure PostgreSQL function (RPC) was created. It automatically increments `user_click_count` if you are logged in as admin, or `public_click_count` if a visitor is browsing publicly.

```sql
-- Drop any legacy function versions
drop function if exists increment_bookmark_click(bigint);
drop function if exists increment_bookmark_click(bigint, boolean);

-- Create the two-argument counter function
create or replace function increment_bookmark_click(row_id bigint, is_logged_in boolean)
returns void
language plpgsql
security definer
as $$
begin
  if is_logged_in and auth.uid() is not null then
    update bookmarks
    set user_click_count = coalesce(user_click_count, 0) + 1
    where id = row_id and user_id = auth.uid();
  else
    update bookmarks
    set public_click_count = coalesce(public_click_count, 0) + 1
    where id = row_id;
  end if;
end;
$$;

-- Grant execution permission to both anonymous visitors and authenticated admin
grant execute on function increment_bookmark_click(bigint, boolean) to anon, authenticated;
```

## 4. Authentication & Dashboard Security Checklist
To secure your Supabase project against unauthorized sign-ups:
1. **Disable Public Signups:** Navigate to Supabase Dashboard $\rightarrow$ **Authentication** $\rightarrow$ **Sign In / Up** and ensure **"Allow new users to sign up"** is turned **OFF**.
2. **Create Admin Account:** Go to **Authentication** $\rightarrow$ **Users** $\rightarrow$ **Add user** $\rightarrow$ **Create new user** to create your personal admin email and password.
3. **URL Configuration:** Under **Authentication** $\rightarrow$ **URL Configuration**, set:
   * **Site URL:** `https://apon77.github.io`
   * **Redirect URLs:** `https://apon77.github.io/**`
